# VFin Agent Notes

- After frontend or server changes, verify the app through the LAN URL, not only localhost.
- Current LAN host is `192.168.31.85`; default app port is `3816`.
- Hard port rule: never start the app on any new or temporary port. Only use the existing/default LAN port `3816`. If `3816` is unavailable or already occupied, do not start another port; stop and report the blocker.
- Minimum completion check for UI/server work: request `http://192.168.31.85:<port>/`, `/login`, and the changed page. If auth is required, log in with the dev demo account and verify the authenticated route returns non-5xx.
- Do not use another port for temporary validation.
- Hard data rule: every displayed financial/market data point must be real data and should be cross-validated with at least two independent sources before being treated as valid. If three serious attempts fail to find a second source, still display the real single-source value when available, but mark it explicitly as degraded/unverified and never present it as fully validated.
- Hard market-multiple rule: stock price, PE, and PB are special high-impact inputs and require mandatory double validation from two independent data sources before display or use in any inference, valuation, or derived calculation. Do not invent, back-solve, estimate, or AI-generate these three fields. If double validation is unavailable, leave the field unavailable/degraded and do not use it for downstream inference.
- Hard data rule: never display demo, placeholder, example, guessed, invented, or AI-fabricated numbers in the UI. If a real value is unavailable or not validated, show an empty/unavailable state and explain what data is missing.
- Hard data acquisition order: this is mandatory for every financial/market data lookup. Step 1: use public structured data channels first, such as official exchange/company APIs, Yahoo Finance, Sina Finance, Tencent Finance, Eastmoney, SEC/HKEX endpoints, or equivalent machine-readable sources. Step 2: if the needed field is not available from public structured channels, download and parse the company's latest available official financial report from the company, exchange, or regulator; prefer the latest quarterly/interim report over an older annual report when both exist. Step 3: only after the first two steps fail, use broader internet search/manual web pages/third-party articles. Cache downloaded reports, public API responses, parsed facts, and source notes locally so future lookups can reuse the source material.
- Hard data freshness rule: always fetch and display the latest available financial report data. Do not use old annual/interim/quarterly data when a newer quarter, interim report, annual report, results announcement, or official filing exists. Older reports may only be used as supporting history or to build TTM/LTM calculations, and the displayed period must clearly identify the latest reporting date used.
- Hard latest-quarter rule: when the latest quarterly report for the subject company and peer is available, use that latest single-quarter period for displayed segment/peer comparisons and valuation inputs. Do not use older annual, interim, or TTM/LTM data in place of the latest quarter. TTM/LTM may only be used when explicitly required by the valuation method, must be labeled as TTM/LTM, and must not be mixed with single-quarter inputs without annualizing or otherwise making periods comparable.
- Hard cache rule: distinguish lightweight live market fields from heavy source material. For simple high-freshness fields such as stock price, PE, PB, dividend yield, and market cap, fetch live/structured public sources first and use cache only as a fallback or for audit trail; still write the fetched raw response and parsed facts back to cache. For financial reports, filings, announcements, parsed statements, peer segment facts, PDFs, and other heavy or slowly changing source material, check the local cache first (`web/src/data/source-cache/**`, company JSON, and any existing parsed text/JSON) and reuse it when it covers the latest required period. Only fetch heavy source material from the network when the cache is missing, stale, incomplete, or does not contain the required latest period/field.
- Hard UI data rule: every asset/company detail page must keep the fixed top key metrics set: PE, PB, ROE, net profit, and dividend yield, in addition to available live quote fields. Do not remove, rename away, or replace these required metrics without explicit user instruction. The app must attempt to obtain these metrics for every asset using the mandatory cache/data acquisition order, cache the raw/parsed source data, and display real values only.
